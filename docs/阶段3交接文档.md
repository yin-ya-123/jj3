## 一、已完成功能

### 3.1 多周期能力实测 + 表结构定案
- 实测确认各周期可用字段不同：日线含 `preclose/turn/tradestatus/isST`；周月线无 `time/preclose/tradestatus/isST`；分钟线仅有 `date/time/ohlc/volume/amount`。
- 分钟线为独立 `time` 字段（YYYYMMDDHHMMSSmmm，17 位），K 线时刻为**结束时刻**；每日根数 5min=48 / 15min=16 / 30min=8 / 60min=4。
- 表结构定案：`daily_bars` 保持不动；新建 `bars` 表**只存 5/15/30/60 分钟线**（唯一约束 stock_code+period+trade_time+adjustflag）；周线/月线不入库，由日线聚合。

### 3.2 Provider 泛化频率 / Collector 支持周期 / 日志加周期字段 / 复权口径迁移
- Provider 新增统一入口 `get_period_history(symbol, period, start_date, end_date, adjustflag)`，非法周期抛错。
- 采集器按 period 分流：d→`daily_bars`，5/15/30/60→`bars`；周线/月线不入库，直接判失败并写日志。
- 每只股票**先同步复权因子再采行情**（区间固定 `1990-01-01` 起），因子失败即中止并写失败日志。
- 口径统一为**不复权**（adjustflag=3）：Provider / 仓储 / 采集器默认 `3`；日线入库不再自动创建股票行（修复自选池污染）。
- `data_sync_logs` 新增 `period` / `adjustflag` 字段。

### 3.3 交易日历 + 增量同步
- `trading_calendar` 表（日期主键 + is_trading_day）；仓储 `save_trade_dates / get_calendar_days / get_trading_days / has_trading_day / get_max_calendar_date`。
- 入口 `scripts/sync_calendar.py`；正式库已同步 2020-01-01 ~ 2026-12-31 共 2557 天（交易日 1697）。
- `sync_daily_bars.py --incremental`：从库内每只股票最新交易日的次日拉取；已是最新或区间无交易日（日历已知）则跳过并写日志；空库/日历未覆盖自动退化为全量。
- `sync_daily_bars.py --ensure-calendar`：增量前自动把日历补齐到结束日（只补缺口）。

### 3.4 完整性检查 + 停牌检查（tradestatus 落库）
- `DailyBar` 新增 `trade_status` 列（`'1'` 正常 / `'0'` 停牌 / NULL 未知）；`save_daily_bars` 落库并归一。
- 新增 `database/repositories/data_quality_repository.py`：`check_data_integrity` / `get_missing_trading_days` / `get_suspension_days`；日历未覆盖时 `calendar_coverage=False`，由调用方先跑 `--ensure-calendar`；NULL 行只统计不误报停牌。
- 入口 `scripts/check_data_integrity.py`，支持 `--codes / --start / --end / --adjustflag / --json`，默认检查自选池，只读不联网。

### 3.5 「🔄 数据同步」界面
- 新增 `data/sync_service.py`：`ensure_calendar_cover` / `run_daily_sync`，CLI 与界面共用。
- 新增 `ui/data_sync.py`，三页签：**同步行情** / **同步日志** / **数据质量**。
- `dashboard_repository.get_sync_logs(limit)` 抽出日志字段映射，工作台最近同步展示复用。
- 修复 `_format_days` 误用于股票代码字符串的 AttributeError。
