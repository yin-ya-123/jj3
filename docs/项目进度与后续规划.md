### 核心原则

1. **稳健优先，不承诺收益。**
2. **允许观望**，不强制产生买卖信号。
3. **不自动下单**，不连接真实券商交易接口，严格遵守 A 股 T+1。
4. **所有预测必须展示依据、置信度和风险**，可解释、可验证。
5. **所有策略必须经过历史回测和验证**，结果必须可复现。
6. **避免未来数据泄漏**：财务数据按实际披露日期取用，模型必须样本外验证。

### 已知数据边界（实测结论）

- Baostock 的 `query_stock_basic()` **不覆盖北交所**（92/43/83/87/88 段返回 0 行）。当前 StockPilot 的股票字典边界 = **沪深两市**（字典 5564 条：SH 2467 / SZ 3097）。
- 分钟线历史最早约 **2020-01-02**；2019 年各月实测均 0 行。
- Baostock 的**前复权锚定当前日期**：股票一旦除权，历史前复权价整体漂移 → 增量追加前复权数据会产生口径混杂、回测不可复现。因此本项目口径定为：**库存不复权原始价（adjustflag=3）+ 本地存复权因子表，复权在计算层完成**。

**关键过程与结论**：

1. **全市场股票字典数量不一致（7445 vs 7345）已定位并修复**，根因三项：
   - 计数口径错配：写入函数返回"提交条数"，断言却拿它与"表内总行数"比较；
   - 数据源污染：全市场快照同时包含股票、指数、ETF、基金、债券，跨市场同码互相覆盖（100 条沪市指数吞掉深市股票）；
   - 市场判定错误：按代码首位反推市场，把沪市债/可转债/指数误标为深市。
   - 最终修法：改用证券基础信息接口、只保留股票类型、市场直接取原始前缀；字典现为 **5564 条，非股票 0 条，批内重复 0 条**。
2. **市场判定规则统一**：北交所段（92/43/83/87）→ BJ；5/6/9 → SH；0/1/2/3 → SZ；其余抛错（7 开头为新股申购配号，非交易代码）。北交所规则按证监会代码段保留，与数据源覆盖情况无关。
3. **批量导入计数口径**：导入返回值区分「新增 / 已更新 / 无效」，无效代码不写库；断言改为**基于导入前快照推导**（`expected_new = 有效码集合 - 导入前集合`），不再依赖数据库初始状态，可重复运行。

### 4.3 阶段 3.2 设计要点（已确认并落地）

- **采集器改造**：默认 `adjustflag="3"`；每只股票**先同步复权因子再采日线**，因子同步失败即中止并写失败日志（避免存下算不出复权价的半成品数据）；同步日志写入 `period` 与 `adjustflag`。
- **采集入口**：命令行脚本 `scripts/sync_daily_bars.py`，支持 `--codes / --start / --end / --period / --adjustflag / --no-factors`，默认同步自选池；`--period` 可选 `d / 5 / 15 / 30 / 60`。
- **不污染自选池**：日线入库不再自动创建股票行（该行为曾把采集到的股票写进用户自选池）。
- **破坏性操作**：清空旧口径日线（594 条前复权数据）并以不复权口径重采，执行前必须备份、脚本要求人工输入确认。
- **因子区间**：复权因子是事件表，必须取上市至今全部除权事件，采集器用常量 `FACTOR_START_DATE = "1990-01-01"` 固定起点。
- **迁移脚本**：`scripts/upgrade_db.py` 先备份 `database/stockpilot.db` 到 `database/backups/`，再补列（`stocks` 4 列 / `data_sync_logs` 2 列）并建缺失表，可重复执行；老日志的 `adjustflag` 默认落 `'2'`，如实反映当时的前复权口径。

**3.2 收尾后剩余的用户操作（破坏性）**：✅ 已于 2026-10-31 执行完毕

```text
1) .venv\Scripts\python.exe scripts\upgrade_db.py     # 备份 + 补列（备份 stockpilot_20261031_105527.db）
2) .venv\Scripts\python.exe scripts\reset_daily_bars.py   # 清 594 条旧口径 -> daily_bars 归零
3) .venv\Scripts\python.exe scripts\sync_daily_bars.py   # 以 adjustflag=3 重采自选池 4 只
```

重采结果：`daily_bars` 792 行全部为 `adjustflag='3'`（4 只 × 198 条，2026-01-05 ~ 2026-10-30）；`adjust_factors` 131 行（4 只）；`data_sync_logs` 新增 4 行 `period='d' / adjustflag='3' / success`。

### 4.4 阶段 3.3 设计要点（已确认并落地）

- **日历表**：`trading_calendar` 一张表一天一行，主键 `calendar_date` + `is_trading_day`；无股票维度。`save_trade_dates` 按主键 UPSERT，可重复执行。
- **日历用途**：增量同步时判断区间内有没有交易日（没有就不必请求数据源）；阶段 3.4 完整性检查找缺失交易日。
- **增量起点**：`incremental=True` 时按每只股票库内最新交易日（同 adjustflag）的次日开始拉；因库存是不复权原始价、除权不改写历史价，增量追加安全。
- **跳过规则**：库内已是最新 → skipped；日历已知且区间无交易日 → skipped；日历未覆盖 → 不拦截，照常请求（防误杀）。
- **空库退化**：库里没有该股票数据时增量退化为全量，从入参起点拉取。
- **日历自动保障**：`--ensure-calendar` 在采集前把日历补齐到结束日（`get_max_calendar_date` 判断，只补缺口；表空则从 1990-01-01 起整段拉），推荐增量时开启。
- **修改文件**：`database/repositories/trading_calendar_repository.py`（新增 `get_max_calendar_date`）、`scripts/sync_daily_bars.py`（新增 `--ensure-calendar`）、`tests/test_daily_collector.py`（FakeProvider 支持日历 + 新增 4 用例）、`tests/test_trading_calendar.py`（已有 3 用例）。

## 七、开发技术原则

1. Python 为主、pip 管理依赖，不擅自升级 Python、不更换依赖管理工具。
2. SQLAlchemy 管理数据库，SQLite 作为初期数据库。
3. Streamlit 作为初期界面；按需拆分模块，保持模块边界清晰、单一职责。
4. 分层开发：数据采集 → 数据处理 → 策略计算 → 模型预测，层间不越界（UI 不直接写 ORM）。
5. 关键功能有自动化测试，测试区分「代码执行成功 / 数据写入成功 / 数据实际持久化成功 / 统计结果正确」。
6. 数据库结构变更**先备份**，不删表、不重建库、不随意改已有字段；注意唯一索引、外键与事务。
7. 不随意覆盖现有文件；沿用既有技术栈，不为简单功能引入大量新依赖。
8. 每个功能完成后测试验收；每阶段完成生成交接文档。
9. 断言与统计口径必须基于**运行时实际数据**，不得假设数据库初始状态（阶段 2 曾因此踩坑）。
10. 投资与工程纪律：不承诺收益、不保证预测准确、允许观望、不自动下单、结果可复现可解释。

## 八、协作方式

- 一次只做一个小任务，不一次性大规模重构，不顺手改无关模块。
- 先分析现有代码（目录、实现、数据库结构、测试、调用链），再给设计和修改计划。
- **未经同意不改文件**；不编造未提供的信息。
- 需要用户执行时，给出可执行的 **PowerShell 命令**（明确执行目录、用途、预期输出、失败处理），优先使用 `D:\cs\python\qt\Jj3\.venv\Scripts\python.exe`。
- 分工边界：**测试脚本由 AI 自行新建并运行跟进**；**长时间等待的脚本交由用户执行**；**涉及真实写入（建表、入库、清库）的功能由用户操作**。
- 用户执行后反馈结果，检查通过再继续下一步。
- 每阶段完成生成交接文档：已完成功能、修改文件、数据库变化、新增依赖、测试结果、遗留问题、下一阶段计划。

## 十一、最终目标链路

```text
数据采集
  → 数据管理
    → 行情分析
      → 基本面分析
        → 技术指标分析
          → 量化策略
            → AI 预测
              → 历史回测
                → 模拟交易
                  → 风险监控
                    → 每日分析报告
```

链路要求（贯穿全程）：

- 数据可自动采集与更新，具备完整性、可追溯性。
- 技术指标计算准确、可解释。
- 基本面数据不含未来信息。
- 策略可独立配置、可复现、可对比。
- 模型可训练、评估、比较，输出概率、置信度与风险。
- 回测贴近真实 A 股规则（含 T+1、涨跌停、停牌、费用与滑点）。
- 模拟交易只做虚拟撮合。
- 每日报告必须写明依据、概率、区间、风险、失效条件与是否建议观望。
